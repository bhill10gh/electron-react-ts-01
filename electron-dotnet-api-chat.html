The best way to add a .NET Web API service to an Electron + React application is to bundle the .NET API with your Electron application and have Electron start the API automatically when the desktop application launches.

This allows you to distribute one desktop application without requiring users to install or manually start the .NET API.

Since you're working with React, Electron, and .NET 10, I'd recommend the following architecture.

1. Recommended architecture

  • Electron main process: Starts, monitors, and stops the .NET API.

  • React: Displays your application and communicates with Electron.

  • .NET Web API: Handles business logic and database operations.

  • Oracle: Your existing database.


The flow is: Electron starts the API, waits until it is healthy, then opens the React UI. React communicates with the API through Electron IPC.

2. Recommended project structure

MyElectronApp/
│
├── electron/
│   ├── main.js
│   └── preload.js
│
├── src/
│   ├── components/
│   ├── pages/
│   ├── services/
│   │   └── api.js
│   └── App.tsx
│
├── backend/
│   └── MyApi/
│       ├── Controllers/
│       ├── Services/
│       ├── Program.cs
│       └── MyApi.csproj
│
├── package.json
├── electron-builder.yml
└── vite.config.ts

Your .NET API remains a separate .NET project, but it gets packaged with Electron.

3. Publish your .NET API

From your API project directory, run:

dotnet publish -c Release -r win-x64 --self-contained true -o ./publish

This generates a standalone version of your API. The output contains your API executable, DLLs, configuration, and dependencies. With --self-contained true, users do not need to install the .NET runtime separately.

4. Configure Electron to package the API

If you're using electron-builder, add the published API folder as an extra resource in package.json:

{
  "build": {
    "appId": "com.smart.desktop",
    "productName": "SMART Desktop",
    "extraResources": [
      {
        "from": "backend/MyApi/publish",
        "to": "backend"
      }
    ],
    "win": {
      "target": "nsis"
    }
  }
}

This places your API outside the Electron ASAR archive, where Electron can execute it.

When packaged, the API will be under resources/backend/.

5. Start the .NET API from Electron

In electron/main.js, use Node's child_process module to launch your .NET executable:

const { app, BrowserWindow, ipcMain } = require("electron");
const { spawn } = require("child_process");
const path = require("path");

let mainWindow;
let apiProcess;

const API_URL = "http://127.0.0.1:5189";

function startApi() {
  const apiPath = app.isPackaged
    ? path.join(process.resourcesPath, "backend", "MyApi.exe")
    : path.join(__dirname, "../backend/MyApi/publish/MyApi.exe");

  apiProcess = spawn(apiPath, [
    "--urls",
    API_URL
  ], {
    windowsHide: true,
    stdio: ["ignore", "pipe", "pipe"]
  });

  apiProcess.stdout.on("data", (data) => {
    console.log(`API: ${data}`);
  });

  apiProcess.stderr.on("data", (data) => {
    console.error(`API Error: ${data}`);
  });

  apiProcess.on("error", (error) => {
    console.error("Unable to start API:", error);
  });

  apiProcess.on("exit", (code) => {
    console.log(`API exited with code ${code}`);
  });
}

During development, Electron starts the API from your project folder. In production, it starts the API from resources/backend.

6. Wait for the API before opening React

Add a health-check endpoint to your .NET API. In Program.cs:

app.MapGet("/health", () => Results.Ok(new
{
    Status = "Running"
}));

Then add this function to Electron's main.js:

async function waitForApi() {
  const maxAttempts = 30;

  for (let i = 0; i < maxAttempts; i++) {
    try {
      const response = await fetch(`${API_URL}/health`);

      if (response.ok) {
        console.log("API is ready");
        return;
      }
    } catch {
      // API is still starting
    }

    await new Promise(resolve => setTimeout(resolve, 1000));
  }

  throw new Error("The .NET API failed to start.");
}

7. Configure Electron startup and shutdown

In main.js, start the API, wait for it, and only then create the window:

app.whenReady().then(async () => {
  try {
    startApi();

    await waitForApi();

    createWindow();
  } catch (error) {
    console.error(error);
    app.quit();
  }
});

app.on("before-quit", () => {
  if (apiProcess && !apiProcess.killed) {
    apiProcess.kill();
  }
});

The startup sequence is:

  • User launches Electron.

  • Electron starts MyApi.exe.

  • Electron waits for the API health check.

  • React application opens.

  • React can communicate with the API.

  • When Electron closes, it stops the API.


8. Connect React to the .NET API

A recommended approach is to use Electron IPC to communicate with the API rather than having React directly access the local HTTP endpoint. This avoids browser CORS complications and keeps API communication in Electron's main process.

In electron/main.js, add an IPC handler:

ipcMain.handle("items:get", async () => {
  const response = await fetch(`${API_URL}/api/items`);

  if (!response.ok) {
    throw new Error("Failed to retrieve items");
  }

  return await response.json();
});

In electron/preload.js, expose the method to React:

const { contextBridge, ipcRenderer } = require("electron");

contextBridge.exposeInMainWorld("electronAPI", {
  getItems: () => ipcRenderer.invoke("items:get")
});

Make sure your BrowserWindow uses the preload script:

webPreferences: {
  preload: path.join(__dirname, "preload.js"),
  contextIsolation: true,
  nodeIntegration: false
}

In a React component:

const loadItems = async () => {
  try {
    const items = await window.electronAPI.getItems();

    console.log(items);
  } catch (error) {
    console.error("Unable to load items:", error);
  }
};

For TypeScript, add src/types/electron.d.ts:

export {};

declare global {
  interface Window {
    electronAPI: {
      getItems: () => Promise<any[]>;
    };
  }
}

You can add additional IPC methods for POST, PUT, DELETE, and other API operations. For production, expose specific operations rather than unrestricted access to arbitrary URLs.

9. Build everything together

Configure your build process to publish the .NET API before creating the Electron installer. For example, add scripts to package.json:

{
  "scripts": {
    "build:api": "dotnet publish backend/MyApi/MyApi.csproj -c Release -r win-x64 --self-contained true -o backend/MyApi/publish",
    "build:react": "vite build",
    "build:desktop": "npm run build:api && npm run build:react && electron-builder --win"
  }
}

Run:

npm run build:desktop

This produces an Electron Windows installer containing your React application and .NET API.

10. Important recommendations

| Item | Recommendation |
|---|---|
| API port | Use a dynamically allocated port or handle port conflicts |
| API binding | Bind only to 127.0.0.1, not all network interfaces |
| API startup | Wait for a health check |
| API shutdown | Terminate the API when Electron exits |
| Security | Keep contextIsolation: true and nodeIntegration: false |
| Database | Keep Oracle connection strings and credentials in the backend |
| Logging | Write API logs to Electron's user data directory |
| Deployment | Publish .NET as self-contained |

Self-contained .NET publishing includes the runtime, but it doesn't automatically include every native dependency your application might require.

Recommendation: Keep the .NET API as a completely separate project within your Electron repository. React handles the UI, Electron manages the desktop application and API process, and .NET 10 handles business logic, Oracle connectivity, and data access.

Are you planning to distribute the Electron application as a portable Windows executable (no installation required), or as a Windows installer? That affects how to configure the .NET API publishing folder and Electron packaging.

startApi();

That error means electron-builder is not installed in your Electron project, or it isn't available in your project's executable path.

1. Install electron-builder

From your Electron project's root directory, run:

bun add -D electron-builder

Since you're using Bun, this installs it as a development dependency.

2. Verify package.json

Make sure your package.json includes electron-builder under devDependencies. The exact version may differ depending on what Bun installs.

3. Update your build script

In package.json:

{
  "scripts": {
    "build:api": "dotnet publish backend/MyApi/MyApi.csproj -c Release -r win-x64 --self-contained true -o backend/MyApi/publish",
    "build:react": "vite build",
    "build:desktop": "bun run build:api && bun run build:react && electron-builder --win"
  }
}

4. Run your build

bun run build:desktop

Alternatively, run the packaging command separately:

bunx electron-builder --win

Use bun run build:desktop so your .NET API is published, React is built, and Electron packages everything together.
